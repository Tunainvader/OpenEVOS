# ADR-0026: Adopt the Craftimon "Lab" design system for the OpenEVOS UI

Status: accepted (v0.4.0.dev0)

## Context
The v0.3 UI reached manual parity but used ad-hoc colours, fixed panel widths and unlabelled icon
buttons. The Craftimon Studio project established tested rules for dense scientific tools: tokenised
colour with measured contrast, computed on-accent labels, inspector rows, grey-not-hide menus, a command
palette, and narrow-window behaviour where labels drop before controls disappear.

## Decision
- `ui/tokens.py` is the single source of colour, type, spacing and state vocabulary (dark and light).
  `ui/theme.py` builds the QSS from tokens; semantic colours are not themeable.
- Bundled Inter (tabular numerals) and JetBrains Mono (OFL); stroke icons on a 24 px grid.
- Every numeric parameter uses `ParamRow`; every command lives in the menu tree and the palette,
  greyed with a reason when unavailable.
- Scientific display mode is the default: linear mappings only, logged into every saved sidecar.
- The image viewport stays dark in both themes.
- `docs/ui/build-kit/` is the hand-off specification for any rebuild, generated by
  `tools/make_build_kit.py` plus hand-maintained BUILD_INSTRUCTIONS.md and ACCEPTANCE.md.

## Consequences
`tests/test_design_system.py` guards contrast and state rules. New widgets must take colours from
`theme`/`tokens`, never literals, and must implement `retint()` if they cache icons.
